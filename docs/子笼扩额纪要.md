# 子笼扩额纪要（当日锁死）

- 纪要编号：SCT-2026-1122-001
- 锁死日期：2026-11-22（当日选定，当日锁死；此后增补/拆笼/入笼/账户/对账五页均以此为唯一口径）
- 适用范围：保证金笼（本仓 `11-bondcage`）拆笼所得子笼的额度增补
- 关联事故：子笼扩额打到父笼编号——子笼额度不动、父笼已关闭仍被改（假绿：增补页返回成功但账实错位）

## 一、唯一正确性口径（二选一，不得混用）

选定 **甲路径：子笼独立扩代整笔**。

乙路径（经已关闭父笼桥接影子单再晋升到指定子笼）**禁用、永不实现**。任何请求声明走乙路径，按
「子笼扩额偏航」处理：记审计 `child_topup_yaw` 并拒写（HTTP 409），账户与子笼零改。

两条路径不得在同一笔业务中混用；偏离本纪要即记「子笼扩额偏航」并拒写。

## 二、甲路径事务口径（唯一允许的子笼扩额实现）

对**目标子笼编号**在同一 SQLite 事务内完成下列全部动作，任一失败则账户与子笼整笔同滚：

1. 抢笼锁 `cage:{子笼id}`；抢不到只在 `contention_log` 留争用痕并 409，不写任何业务。
2. 载入目标子笼行并按其 `id` 定位（不接受任何父笼编号回退/桥接）。
3. 从子笼所属当事人保证金账户的**可用余额**（balance − frozen）划入：
   - 可用不足 → 拒写，账户与子笼零改；
   - `bond_accounts.frozen += amount`（balance 不变，资金仍在系统内冻结）。
4. 抬额升代：目标子笼 `amount += amount`、`available += amount`、`generation += 1`。
5. 登记 `topup_jobs`（状态 `子笼扩额成功`，模式 `子笼独立扩代整笔`）。
6. 写审计 `child_topup`，载荷含子笼编号、扩额金额、扩前代/扩后代、账户键、job_id。
7. 同事务提交；提交后断言：仅目标子笼升额，父笼行（含已关闭父笼）金额、可用、状态、代次零改。

## 三、与父笼切断

- 子笼扩额 SQL 一律以 `WHERE id=:子笼id` 定位，禁止出现父笼 id 写路径、禁止经父笼桥接回写。
- 父笼拆笼后状态为 `已拆笼`（关闭态）：对父笼的任何扩额/入笼写动作一律拒绝并记偏航。
- 父笼行在子笼扩额前后须逐字段不变（amount/available/status/generation）。

## 四、并发口径

- 两人同时扩同一子笼：后到者抢 `cage:{子笼id}` 锁失败，只留 `contention_log` 争用痕，
  返回 409；子笼额度、账户、topup_jobs 均不得由后到者产生任何业务写入。

## 五、五页同源口径

增补页、拆笼页、入笼页、账户页、对账页的账实均以同一 SQLite 母仓（`data/app.db`，库文件不换）
为唯一来源：

- 账户侧：`bond_accounts.frozen` 恒等于全部活笼（含独立子笼）`available` 之和；
- 笼侧：每只笼 `available + 同代已拨付 + 同代已罚没 == amount`；
- 子笼父子关系仅作谱系展示（`parent_id`），不参与任何金额回写。

## 六、变更纪律

- 禁止只改增补页笼号提示；禁止无测直线改文案。
- 先落「扩额打到父笼」假绿事故夹具，再落错位失败测、双人同扩争用失败测，两条失败测见红后
  才准改增补服务、拆笼服务、入笼服务与账户服务，并改增补页与拆笼页。
- 库文件保持 SQLite 不换；页面登录保留。
